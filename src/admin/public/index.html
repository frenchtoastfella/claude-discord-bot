Checklist

Live status of everything the bot needs before it can answer a message.

Step 1 — Enable the Message Content intent

Reading message text is a privileged intent. Until it's switched on, Discord refuses the connection outright with Used disallowed intents.

  1. Open discord.com/developers/applications and pick your application.
  2. Go to the Bot tab and set the toggles exactly as below.
  3. Click Save Changes at the bottom of the page.
  4. Restart this process — intents are only requested at login, so a running bot won't pick up the change.
Toggle on the Bot tabSet toWhy
Message Content Intent ON Required. Without it every message arrives with empty text and the bot has nothing to answer.
Server Members Intent off Only needed to read member lists and join events. This bot never does.
Presence Intent off Online/offline status. Unused.
Requires OAuth2 Code Grant off Leave it off — turning it on makes the Step 2 invite link fail with an OAuth error.
Public Bot your call On lets anyone with the link add it to their server. Off means only you can — the safer choice for a private bot.

These are intents — what the gateway is allowed to send you. They're separate from permissions, which are what the bot may do inside a server and are attached to the invite link in Step 2. You need both.

Step 2 — Invite the bot to your server

This link is generated from your own application id and requests exactly the permissions the bot uses — nothing more.

Which permissions, and why

The link above already requests these. Tick exactly these boxes if you'd rather build the URL yourself under OAuth2 → URL Generator (scope: bot).

You need Manage Server on the target server to complete the invite. To restrict the bot to certain channels, invite it and then use Discord's own channel permissions — or list channel IDs under Always-answer channels in Configuration.

Step 3 — Point it at your documentation

Without a docs repo the bot answers from general knowledge only.

  1. Open Configuration and set Repository URL and Branch.
  2. Private repo? Use an HTTPS URL with an embedded token, e.g. https://x-access-token:<PAT>@github.com/org/repo.git, or rely on your machine's git credential helper.
  3. Back on Overview, click Pull & reindex.

Step 4 — Talk to it

By default the bot replies when addressed, and stays quiet otherwise.

  • @mention it in any channel it can see.
  • Reply to one of its messages to continue a thread.
  • DM it directly.
  • Want it to answer everything in a support channel? Add that channel to Always-answer channels in Configuration — either its name (bot-discussion or #bot-discussion) or its numeric ID (Developer Mode on → right-click the channel → Copy Channel ID). Threads inherit their parent channel.

If it still doesn't respond

Used disallowed intents in the logStep 1 isn't done, or the process wasn't restarted after saving.
Connects, but ignores every messageMessage Content intent is off, so message text arrives empty. Same fix as Step 1.
Silent in one channel onlyThe bot lacks View Channel / Send Messages there. Check that channel's permission overrides in Discord.
An invalid token was providedReset the token in the portal and paste it into .env (not .env.example).
Answers, but knows nothing about the projectNo docs indexed — see Step 3, then check the file count on Overview.
